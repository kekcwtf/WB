# WB Profit Desktop

Настоящее локальное приложение PySide6 для Windows. Браузер и внешний сервер не требуются. **Разработка продолжается; готовность к ежедневному финансовому учёту на реальном магазине ещё не подтверждена.**

## Что реализовано

- Загрузка официального API WB в фоновой нити: финансовая детализация, список финансовых отчётов, заказы, продажи и возвраты, карточки, рекламные затраты, комиссии FBW и остатки.
- Рекламный кабинет: счёт, лимит взаиморасчётов, бонусы, пополнения и потребление кампаний — раздельно. Статистика по кампаниям и артикулам WB, ДРР при достаточной статистике и подтверждённой выручке. Сумма рекламных заказов не выдаётся за выручку/ROAS фактических продаж.
- Кнопка «Обновить сейчас», автоматическое обновление каждые 30 минут во время работы, кеш, возобновление страниц, ограничения запросов с сохранением между запусками, повтор временных сетевых ошибок. После исчерпания HTTP-попыток сохраняется расписание восстановления неудачных источников; готовность проверяется раз в минуту с увеличением задержки. При доступном системном мониторинге появление сети возобновляет отложенную работу, сохраняя ограничения WB. Ручное обновление обходит прикладной кеш, но соблюдает реальные лимиты WB. Базовые токены обновляются реже в соответствии с ограничениями WB. Карточки запрашиваются с сохранённой позиции updatedAt/nmID.
- Начальная история: финансовые отчёты с 29.01.2024; оперативные заказы и продажи за доступные 90 дней. Финансовая история повторно читается целиком раз в неделю, в остальных проходах используется перекрытие 35 дней.
- SQLite с исходными ответами, нормализованным реестром и историей исправлений. Удаления финансовых строк применяются после завершения всего интервала, остатки сохраняются снимками, рекламные списания — месячными снимками.
- Decimal, разделение выплат и прибыли, сверка с независимым `bankPaymentSum`, неизвестные операции и расхождения. Встроенные комиссии и эквайринг не вычитаются из `forPay` повторно.
- Режим «Заказы и выкуп»: когорты по дате заказа, связь исходов по srid и точному SKU, открытые/неоднозначные исходы отдельно. Процент доступен только для завершённой когорты с покрытой историей; возвраты после покупки показаны отдельно. Модель пересчитывается по сумме заказов размеров, без усреднения процентов.
- Таблица SKU, фото с официальных CDN без передачи токена, реквизиты и размеры карточек, категории по алфавиту, поиск и фильтры, группировка размеров по модели, карточка расходов и объяснение убытков из операций.
- Связь возвратов с единственной исходной продажей по srid и баркоду: восстановление себестоимости по дате исходной финансовой операции, включая продажи вне выбранного периода. Неоднозначные связи не подставляются.
- Сравнение с предыдущим равным периодом только при достаточно полных и сверенных данных.
- Финансовый обзор: продажи и возвраты отдельно, статьи расходов WB, расчётные валовая и операционная прибыль, УСН/НДС, маржинальность, ROI закупки и ДРР с индивидуальными статусами достоверности. Формулы — в подсказках; неизвестные суммы не подменяются нулями.
- График расчётной чистой прибыли по дням с контролем суммы периода, отдельный режим до НДС/УСН, разрывы на неполных днях и таблица дневного расчёта. Налоги распределяются с сохранением копеек; неподтверждённые дни не подменяются нулями.
- Экраны рекламы и склада, оценка запаса, фильтры возможных неликвидов и высоких расходов хранения. Прогноз цены по историческим расходам с комиссией FBW из кеша при наличии и консервативной оценкой точки безубыточности.
- Несколько магазинов, себестоимость по SKU с датой действия, явно назначаемая общая себестоимость, история налоговых ставок с датами действия, распределение общих расходов, ввод и редактирование внешних расходов, светлая/тёмная темы, резервное копирование SQLite.
- Проверка ID продавца через официальный /api/v1/seller-info: новый токен другого продавца не смешивает данные существующего магазина.
- Windows Credential Manager: токены не записываются в SQLite или логи. Заявленные права читаются локально, фактический доступ подтверждает ответ API. Токен требуется сохранить один раз для каждого магазина.

Рабочий режим не содержит демонстрационных продаж. Синтетические операционные данные находятся только в тестах. Отсутствие данных не означает нулевые расходы или прибыль.

## Проверка документации

Блокировка HTML-страниц HTTP 498 больше не является препятствием: доступна официальная YAML-выгрузка `https://dev.wildberries.ru/api/swagger/yaml/ru/13-finances.yaml?region=ru` и другие схемы того же раздела.

Проверенные схемы сохранены в `docs/api`, контрольные суммы и исходные URL — в `docs/api/manifest.json`. [Карта источников](docs/API_SOURCES.md) объясняет выбор методов. Сторонний SDK использован только для обнаружения URL; операционные данные приложение получает непосредственно от WB.

## Ограничения финансового результата

**Расчётная чистая прибыль появляется только при полном покрытии периода, закрытом отчёте, успешной независимой сверке, известной себестоимости и подтверждённых пользователем налоговых настройках.** Налоги остаются расчётными обязательствами.

Пока не реализовано достоверное сопоставление рекламных затрат с финансовыми удержаниями WB. При наличии рекламных расходов или списаний без даты полная чистая прибыль блокируется с объяснением: программа не вычитает рекламу дважды и не считает её нулевой. На отдельном экране доступны выставленные затраты, статистика потребления, пополнения и состояние счёта. Номера/суммы разных отчётов сами по себе не считаются подтверждённой связью. Записи без достоверной даты или часового пояса не приписываются выбранному дню; валюты не конвертируются и не смешиваются автоматически.

Себестоимость связанного возврата восстанавливается по исходной финансовой операции. При отсутствии однозначной связи она не подставляется по текущей цене закупки. В разделе «Сверка» доступна проверка возвратов: точная исходная продажа, количество и суммы всей связанной истории, себестоимость по исходной дате, разные кварталы и настройки налогов. Оценки НДС в возвращённой цене и УСН с суммы используют исходные подтверждённые настройки и не являются вычетами или проводками. Налоговая периодизация возвратов пока не подтверждается автоматически и блокирует полную чистую прибыль; отрицательная выручка не объявляется правом на возврат налога. Компенсации, особые корректировки, новые поля схемы, неопределённые операции и необъяснённые остатки `forPay` также блокируют полный результат. При достаточных данных таблица показывает расчётную чистую прибыль SKU после налогов. Карточка товара и модели показывает ту же прибыль, отдельные УСН/НДС и общие расходы, прибыль на единицу, маржу и ROI; сумма статей проверяется на совпадение с итогом. Иначе показан результат до налогов с явным пояснением. Общие расходы остаются у магазина либо распределяются по выручке по выбору пользователя; сверка сохраняет итог магазина.

История ставок сохраняется с датами действия; ставки будущих периодов не меняют прошлое. Настройки без даты не распространяются на старые операции автоматически. Разбивка налогов по версиям и кварталам доступна в разделе «Прибыль и расходы».

Налоговая модель УСН «Доходы» исключает включённый НДС из базы реализации. Льготы, взносы, вычеты, годовые ограничения, особенности иных доходов и точное налоговое обязательство автоматически не определяются. Юридическая применимость модели не подтверждена. Пример 4% УСН / 5% НДС не применяется без явного назначения и подтверждения.

В разделе «Склад» остатки и скорость продаж относятся к последним 30 календарным дням, а проводки хранения — к периоду, выбранному в верхней панели. Возможный неликвид — аналитический сигнал по явно указанному порогу, а не доказанная убыточность. Пробелы истории и устаревшие снимки отключают прогноз; общие суммы хранения не копируются на каждый размер. Пороги и фильтры доступны в том же экране, категории отсортированы по алфавиту.

## Windows

Процесс `.github/workflows/windows-build.yml`: Windows + Python 3.12 → тесты → PyInstaller `--windowed` → проверка запуска упакованного приложения → установщик Inno Setup → проверка установленного EXE, ярлыка, переустановки и удаления с сохранением базы и секрета Windows Credential Manager. Артефакт называется `WB-Profit-Desktop-Windows`; после успешных проверок он содержит установщик, `verification.json` и `SHA256SUMS.txt`.

**Windows workflow в этой работе не запускался; проверенного Windows EXE или установщика ещё нет.** Linux-сборка не доказывает работу Windows Credential Manager, установки, ярлыка и обновления на Windows 11.

После получения проверенного установщика пользователь запускает его двойным щелчком, открывает ярлык, добавляет магазин и сохраняет токен в настройках приложения. Токен не нужно отправлять в чат. Для обновления каждые 30 минут и списка финансовых отчётов нужен персональный/сервисный токен; базовые токены ограничены WB сильнее.

База находится в Qt `AppLocalDataLocation`, отдельно от каталога установки. Одновременно работает один экземпляр программы. При ошибке чтения базы во время запуска можно выбрать резервную копию: она станет новой рабочей базой, а исходные файлы останутся на месте. Имя восстановленной базы сохраняется в `active-database.json` в той же папке. Установщик не удаляет пользовательскую базу. SQLite-копия не содержит секреты из Windows Credential Manager. Фото кешируются отдельно и могут быть загружены повторно.

В разделе «Настройки» можно создать резервную копию и восстановить базу из файла. Операция сохраняет данные всех магазинов и историю; токены Windows Credential Manager в неё не входят. Перед восстановлением программа проверяет совместимость файла и автоматически сохраняет текущую базу в папку `backups` рядом с рабочей базой. Магазины и настройки обновляются в окне после восстановления. Копирование выполняется в фоне, синхронизацию на это время нужно завершить.

Автокопии включены по умолчанию: одна версия на московский день, текущая обновляется не чаще раза в 4 часа, хранятся до 7 ежедневных версий. Параметры доступны в настройках; там же можно открыть папку копий. Копирование выполняется между загрузками WB, в фоне. Старые собственные версии удаляются после успешной проверки новой; ручные файлы и копии перед восстановлением сохраняются. Программа должна быть открыта. Для защиты от поломки диска сохраняйте копии также на другом носителе. При переносе на новый компьютер токены нужно добавить в приложении заново; в чат их отправлять не нужно.

## Для разработки

Работайте в существующем изолированном checkout; отдельный Git worktree не нужен.

```bash
cd /workspace/WB
python3 -m venv /workspace/wb-profit-venv
/workspace/wb-profit-venv/bin/python -m pip install -r requirements-build.txt
QT_QPA_PLATFORM=offscreen PYTHONPATH=src /workspace/wb-profit-venv/bin/python -m unittest discover -s tests -v
QT_QPA_PLATFORM=offscreen PYTHONPATH=src /workspace/wb-profit-venv/bin/python -m wb_profit.desktop --smoke-test
```

В графической сессии запускайте `PYTHONPATH=src /workspace/wb-profit-venv/bin/python -m wb_profit.desktop`. API-токены на Linux сознательно не сохраняются: безопасный рабочий вход предназначен для Windows Credential Manager. В режиме `offscreen` автоматический запуск синхронизации отключён.
